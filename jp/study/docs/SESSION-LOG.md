## 关键设计决策

**选项确定性打乱**。题目数据里正确答案写在第一位（便于人工编写和校对），
运行时用种子 `index*7919+17+set*131` 的线性同余打乱。好处是选项位置固定（重做同一题
位置不变，不会因为位置变了而「重新思考」），又不会让答案总在第一个。

**三套题分开存作答记录**。`st.a` 是数组（每套一个 object），切换题库互不影响。
从旧 key `jp-setsuzoku-100-v1` 迁移时把旧记录放进第 0 套。

**考试模式的题按原题号排序**。随机抽题后 `sort((a,b)=>a-b)`，保证仍是由易到难，
因为每套的题号顺序就是难度顺序。

**印章用「正解／誤」而不是「○／×」**。○ 在 Noto 里字形太细，放大后像空心圆，辨识度差。

**讲义的 × 例句选「语法没错但场合不对」的**。这是整套材料的核心特色——用户是实务需求，
教科书式的语法错误对他没价值，真正会踩的坑是敬语方向、语体崩坏、逻辑自相矛盾。

**两份讲义分工**：`benseki` 是「容易混的 16 组」（学习者视角的高频混淆点），
`fukushu` 是「这次会话问过的全部表达的归类」（个人化的复习笔记）。两者有少量重叠，是有意的。

## 后期对话里形成的教学框架

会话后半段逐渐浮现出一套解释框架，用户确认「these are all connected」，
现已写进 `CLAUDE.md`：日语商务文型的大半是「自己要露出多少」的调节装置，
分四条正交的轴（评价 / 语体 / 视点责任 / 信息源确信度）。

还有一条实务建议，值得保留在材料里（尚未写入）：

> 不是记更多选项，而是**压缩决策树**。实务写作每个功能定一个默认值，
> 只在有正当理由时偏离：原因用 ため（文書）/ ので（メール），逆接用 が，
> 依赖用 ご〜いただけますでしょうか，意见用 〜かと存じます，拒绝用 〜いたしかねます，
> 追加用 また／なお，结论用 つきましては。其余的表达是**认读**用的，不是生产用的。
> 固定块组句（お世話になっております → 〜の件でご連絡いたしました → つきましては… →
> お手数をおかけしますが）比逐词造句快得多，而且不会出语体裂缝。
