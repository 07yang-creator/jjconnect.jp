# 内容编写规范

用户是矢野（Yano），在东京经营 株式会社JJconnect（数据・IT・不动产投资）。
日语学习目标是**实务**：写商务邮件、合同、通知、对客交涉，不是应试。
对话用中文，材料里的说明也用中文，例句用日文。

## 贯穿全部材料的框架：四条轴

所有辨析最终都挂在这四条轴上，写新内容时应明确它落在哪条轴：

| 轴 | 低 ← → 高 | 代表 |
|---|---|---|
| ① 评价的有无 | 中立 ↔ 含说话人的褒贬 | いちいち / 一つ一つ、せいで / ため、言われた / ご指摘いただいた |
| ② 语体高度 | 口语 ↔ 书面・公文 | から / ので / ため / につき、やる / 行う / 実施する |
| ③ 视点与责任 | 他动词点明主体 ↔ 自动词淡化 | 見つけられない / 見つからない、ことにする / ことになる |
| ④ 信息源与确信度 | 断定 ↔ 传闻・推量 | です / かと存じます / 可能性がございます / と言われています |

实务结论：**日语商务文型的大半是「自己要露出多少」的调节装置**。
四条轴正交，调一条不能中和另一条（例：「対応しようとしないので」把 から 换成 ので，
语体柔和了，但「ようとしない」的非难仍在，必须同时改成「対応が進んでおりません」）。

## 写题目的规则

1. **错误选项必须是真干扰项**，即同类、同接续、学习者真会犯的错，不要凑数。
2. **× 例句优先选「语法没错但场合或逻辑不对」的**，这是材料的特色，也是用户实际会踩的坑。
   典型：
   - 「ご要望に基づいて柔軟に対応します」—— 自相矛盾
   - 「ご要望にはお応えしかねません」—— 把拒绝说成了反义
   - 「部長、お持ちしてあげます」—— 敬语方向错
   - 「体調が悪いから、休ませていただけませんか」—— 对上司生硬
   - 道歉邮件里的「遅れちゃいまして」—— 语体崩坏
3. 每套 100 题，5 个等级各 20 题，**顺序由易到难**。
4. 选项写进数据时**正确答案放第一位**，不要自己打乱（运行时确定性打乱）。
5. 解析一句到两句，说清**判断依据**（接续限制、后句限制、褒贬、语体），不要只说「这里要用 X」。
6. 写完必须跑 `./check.sh`，并用 Playwright 截图确认渲染（见下）。

## 写讲义的规则

- 每组结构固定：**区别表 → ○× 例句 → 一句记法（tip）**。
- `lead` 写「判断顺序」而不是定义，例：「先看后句能不能出现意志・请求・命令，再看前后顺序」。
- tip 必须是能脱口而出的一句话，不是总结段落。
- 表格列数 2–3 列，第一列是表达本身（渲染时自动套日文字体）。
- 涉及商务的组，尽量给出「口语 → 书面」的替换表，这是用户最用得上的部分。

## 校验

```bash
./check.sh                 # node --check + 题数/结构校验
python3 tools/shot.py      # Playwright 截图（需 pip install playwright && playwright install chromium）
```

渲染必查项（过去真出过问题）：
- 混入简体字：`間違い` 曾被写成 `间违い`。`tools/check_mixed_script.cjs` 可扫。
- 变量名撞 window 全局：`const top = ...` 会抛 `Identifier 'top' has already been declared`，整页白屏。
- 移动端 390px 宽下，题干与右上角印章重叠（`.stem` 需 `padding-right`）。
- 印章用「正解 / 誤」，不要用 ○ ×（字形在 Noto 里太细，缩放后像空心圆）。

## 设计

三个页面共用一套 token（纸色 `--paper:#EEF2EF`、墨色 `--ink:#1C2A30`、蓝 `--ai:#27466F`、
朱 `--shu:#C23B2A`、绿 `--midori:#2C7652`），含 dark mode。日文用 Zen Kaku Gothic New，
中文用 Noto Sans SC，靠 `[lang=ja]` 切换。新页面沿用同一套，别另起炉灶。

## 不要做的事

- 不要把例句换成更「标准」的教科书例句——现有例句都是按用户的业务场景（不动产、合同、
  对客邮件、数据核对）挑的，这是材料的价值所在。
- 不要加后端或账号系统。页面必须保持单文件、可离线、可直接上传到任何静态主机。
- 不要改 localStorage 的 key，否则用户已有的作答记录全丢。
